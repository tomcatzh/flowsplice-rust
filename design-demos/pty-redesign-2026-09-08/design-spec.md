# PTY 界面设计规格：多 Home 修订稿

历史状态：这是 2026-09-08 设计评估阶段的规格。用户随后已批准 A 和手机流程并授权开发；当前决定见[已批准的实现方向](direction-approved.md)。下面的“当前代码”和“只研究”描述仅指评估时的 b02625a 基线。

## 已确认需求

一个客户端必须能够保存、随时连接并同时使用多个 Home，包括多台 VPS 和 Mac。新建 tmux 会话时先弹出命名界面，确认名称后再创建远端 shell，并以读写模式进入。会话列表需要同时展示名称、创建时间、最近连接时间和当前连接数。

产品分为三个层次：Home 列表管理已授权入口；某个 Home 的会话页列出远端仍存在的会话；全局“已打开终端”跨 Home 管理本机实际加入的视图。页面切换不会断开其他 Home，也不会重新创建远端会话。同一 Home 内多个会话与跨 Home 多连接是不同能力，界面都需要支持。

## 本轮采用的定义，供评估

- 创建时间：远端 tmux 会话成功建立的时间，重连不修改。
- 最近连接时间：任意客户端最近一次成功加入该会话的时间；不是最后输入时间、断开时间或命令历史。首次创建包含首次加入。
- 当前连接数：当前实际加入会话的 attachment 数量，包含读写和只读；只连接 Home 后浏览列表不计入。同一设备若允许多视图，各 attachment 分别计数；可展开查看设备名称和读写状态。不要把 attachment 数直接标成“设备数”。
- 名称：Home 保存的会话元数据，各客户端展示同一个名称，内部稳定 ID 继续用于识别。创建流程先提示名称；是否允许重名、是否提供重命名、名称长度等在逐页交互规格中再确定。
- Home 的“已连接”表示本机当前业务连接状态，不表示服务器必然在线。未连接的 Home 不显示貌似实时的会话数量；缓存若将来加入，必须标记为缓存。
- 一个 Home 断线仅让该 Home 的输入失效，其他 Home 继续使用。重连后回到该 Home 的会话列表，不重发输入，不自动补建 shell。
- 关闭标签只退出本机视图，不结束 tmux 会话。保留无删除 session API、一个写入者和警告后强制接管的既有规则。
- 多 Home 的保存和同时连接，不意味着手机后台保活。本轮仍沿用前台使用、业务连接按需建立的边界。

## 当前代码核对结果

| 需求 | 当前实现 |
| --- | --- |
| 一个 Home 的多个会话/本机标签 | 已有 |
| 创建时间 | 协议已有，现有 UI 未展示 |
| 创建前命名 | 没有；New 只有行列数 |
| 最近连接时间 | 没有相应会话字段 |
| 当前连接数 | Home 内部跟踪 attachment，但协议未输出数量 |
| 一个客户端同时连接多个 Home | 没有；Apple/Android 加载单份 business.json 并拥有单个 native handle，actor 只持有一个 PtyClient |

核对位置：`pty/protocol/src/lib.rs` 的 Session/New；`pty/home/src/session.rs` 的 snapshot/attachments；`pty/native/src/engine.rs` 的 NativeOptions/actor；`pty-apple/Sources/TerminalHost.swift` 和 `pty-android/.../MainActivity.kt` 的单个配置与句柄。不能把底层可以实例化多个对象等同于现有应用已经支持多 Home。

## 页面地图

Home 列表 → 添加/授权某个 Home → 等待该 Home 批准 → 该 Home 会话列表 → 新建并命名或加入已有会话 → 独立终端页面。

全局已打开终端页聚合不同 Home 的视图。终端始终显示 Home 名称和会话名称，避免同名会话混淆。桌面提供三种待评估布局：A 横向标签，B 原生浅色分栏，C 按 Home 分组的纵向会话工作台。手机独立导航与键盘占位，iPad 利用横屏空间。设置独立成页；字体和主题是显示偏好提案。

接管使用独立确认：当前 Home、会话名、当前写入设备和明确后果。被接管端变为只读并提示，不能靠颜色变化让用户猜。断线和会话结束是不同状态。

## 实现边界

本轮只研究和出图。多 Home 是客户端连接管理与授权配置的新增设计；命名、最近连接时间和连接数需要 Home/PTY 元数据与接口设计，不能仅靠前端换皮伪造。会话名称和最近连接时间应随 tmux 会话跨 PTY Home 进程重启保留；活动连接数在连接恢复前不能沿用过期值。具体持久化与恢复机制尚未选择。

PTY 消息当前使用严格字段解析；新增字段/操作必须先设计兼容策略，不能直接往旧消息增加字段并声称兼容。既有证书、FlowSplice 加密传输与已发布普通 Travel 的兼容约束继续有效。此处未决定 PTY 协议版本或上线方式。

添加 Home 页面只接入合法授权，不能随意输入目标后绕过 Super Home 审批。授权入口使用何种邀请/描述符导入交互还需细化；日常连接不再重复选业务。不把 SFTP、SSH 密钥库、广播命令、AI、history/audit 或后台保活加入本轮。

## 评估边界

PNG 是静态方向草稿，不能点击，不证明实现或运行状态；终端文本和数量均为示例。图像生成可能使次要状态标签或选中样式不一致，最终语义以本规格为准。尤其读写属于当前终端 attachment，不能放成整个应用的全局权限；只有本机已加入的视图才能出现在“已打开终端”；全局 Home 管理入口必须一直可达。方向选定后用逐页交互规格消除这些细节偏差，再开发。

当前交付为五张修订效果板：三套桌面方向、一张手机五页面流程、一张 iPad/关键状态板。初始单 Home 的六张图与原规格保留于 initial-v1，仅用于设计历程，不作为当前产品范围。
