## 需要解决的使用问题

使用者是维护自己电脑与服务器的个人用户，会在 Mac、iPad 和 Android 手机之间切换。远程业务已打通；这轮的目标是让它成为可以每天长期使用的终端工具。当前截图把首次配置、密码输入、连接控制、服务消息、远端会话列表、本机标签、读写控制和终端一起放进一个滚动页面，导致终端只有很小的可用高度，完整 UUID 占据主要视觉位置，常用动作与低频动作没有层次。三套初稿必须解决同一组问题，不能仅仅更换颜色。

共同的产品模型是：一个已授权的业务入口，多个持久化远端会话，以及当前设备实际打开的终端视图。远端会话仍然存在，不等于本机标签仍然打开。第一次注册完成后，配置应退到独立页面；平时进入终端时，主要空间应属于终端文本。主界面不反复要求选择 Home 或业务，业务描述符已经指定目标。输入 Relay 地址发生在注册流程中，不变成 SSH 主机管理表单。

## 页面与状态清单

1. 首次连接设置：Relay 地址与私钥密码，绑定业务说明；不增加 Home/服务选择器。
2. 等待批准：独立页面显示校验码、等待状态和返回入口；不把内部 phase 字符串显示给用户。
3. 已配置入口：显示当前绑定目标，提供连接与连接设置入口；没有业务连接时不假装拥有实时会话列表。
4. 会话列表：只在连接后展示远端仍存在的会话。清晰呈现短 ID、创建时间、当前写入者。新建默认读写。完整 ID 放到详情，列表不要成为一排巨大 UUID 按钮。
5. 终端工作页：独立页面，Mac 使用紧凑标签和物理键盘，正文区域尽量占满窗口。只读与读写通过文字、图标及颜色共同表达；关闭本机标签只断开当前视图。
6. 多个已打开终端的切换：桌面可横向标签或可收起的纵向列表；手机使用独立切换页或底部抽屉。页面导航不会误发远端 exit。
7. 接管确认：明确显示当前写入设备，按钮写“接管读写”；确认后远端切换为只读。被接管设备显示明确提示，不能只换一个颜色。
8. 连接中断：终端停止接受输入，提示重新连接；重新连接后回到远端会话列表，用户选择已有会话，不盲目新建或重发输入。
9. 会话结束：区别于网络中断，提供返回列表与新建入口，无重连到已结束会话的假按钮。
10. 设置与连接详情：独立页面容纳绑定业务、连接状态和显示偏好。字体/主题等偏好属于本轮提案，未声称现有代码已支持。

## 三个方向

A — 专注终端：最接近 Termius 的水平标签思路。管理页和终端是同级标签，进入终端后隐藏管理侧栏。深灰底色、少量薄荷绿强调，密度紧凑。重点比较终端面积与切换效率。

B — 原生分栏：浅色管理界面与深色终端区，固定但可收起的侧栏，列表/详情分栏。更强的 Mac 和 iPad 原生工具感，手机改为逐级导航。重点比较熟悉程度和触控目标。

C — 会话工作台：窄导航轨配纵向打开终端列表，长标签始终可见，终端工作区可独立进入专注状态。暖石墨与薄荷色。重点比较同时打开较多终端时的可辨识性，不能用大卡片或虚假监控数字增加视觉密度。

## 已有边界与待评估提案

已确认保留：一个写入者、多个只读加入者、警告后强制接管、写入者决定终端尺寸；无删除远端 session 按钮；shell 最后退出后 tmux 会话消失；Mac 没有鼠标点击的虚拟键盘行；手机保留输入辅助；加密与协议不在本轮修改。

这轮不会把 Termius 的 SFTP、SSH 密钥库、主机分组、云同步、命令广播、AI 补全、history 或 audit 顺带加入范围。截图中的会话数据是明确标记的设计示例，不能伪装成实时生产数据。只使用当前协议确实提供的会话 ID、创建时间和写入者；当前命令、工作目录、CPU 和内存不作为服务端元数据展示。

效果图中的搜索、短 ID 展示、页面导航、打开终端切换和字体设置均为待评估的界面提案。会话重命名和持久化本地别名暂不画入，避免让名字看似已经具备跨设备同步能力。
