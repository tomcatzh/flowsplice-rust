# FlowSplice 0.4.3

FlowSplice 0.4.3 completes the Carrier race for Relays that have more than one data address.

## Fix

- Travel now races every data address of a Relay route, in the same way the Carrier race
  already runs every Relay and management address. The first address that reaches the Relay
  and completes the pinned business TLS handshake with the Home carries the route; the other
  attempts are dropped. Only one Travel side can claim a route, so the Relay rejects later
  arrivals.
- Before this release, the data addresses were tried in turn, each with the full handshake
  timeout, which equals the default Carrier race timeout. An address that dropped packets used
  up the whole attempt, and an address that accepted TCP without being a Relay ended it, so the
  next address was never tried. A Travel whose network could reach the Relay only through its
  enrollment-time or operator alias address could not open any Carrier.

## Scope and verification

The change is limited to the Travel runtime in `flowsplice-travel-core`, and so reaches the
Travel SDK, the command-line Travel and the generic native clients. Server, Relay, Home,
protocols, configuration, certificates and persisted state are unchanged; a 0.4.3 Travel works
with 0.4.1 and 0.4.2 Relays.

Regression coverage adds race unit tests (a silent first address, failure reporting, release of
losing attempts) and an end-to-end check in which the first data address of every Relay accepts
TCP but is not a Relay. The release workflow additionally runs the workspace tests, strict lint
checks, real TLS regressions, standalone SDK checks and current-version end-to-end tests.

Since 0.4.2, the private PTY terminal product has moved to the independent Vaultty project,
which consumes FlowSplice through the SDK crates.

## Distribution

This is a source-only release. Native installers and deployment packages are built
privately; no crates.io packages or private binary assets are published.
Git consumers should select `tag = "0.4.3"`, update their FlowSplice dependencies,
and commit the resulting lockfile. Earlier tags remain unchanged.

See the [SDK guide](../../crates/README.md) and
[private Travel packaging](../PRIVATE_TRAVEL_PACKAGING.md).
